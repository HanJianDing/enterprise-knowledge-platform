# 企业知识平台

基于 RAG 的企业知识检索与问答平台，面向制度查询、部门资料检索和知识维护场景，提供从文档入库、权限过滤到检索增强问答的基础流程。

## 功能概览

| 模块 | 能力 |
| --- | --- |
| 知识入库 | 文档上传、解析、分块、向量化、处理状态查看；扫描 PDF 可结合 OCR 处理 |
| 知识维护 | 管理员维护页面、文档版本查看、差异比较及重新处理 |
| 智能问答 | 流式回答、多轮会话、历史记录、反馈与引用来源展示 |
| 权限管理 | 管理员、员工、审计员；知识库读、上传、管理权限及部门隔离 |
| 工具与接入 | 工具调用、MCP 客户端与服务端、OpenAI 兼容接口子集、Dify 检索接口及 Python SDK |
| 评估与审计 | 检索评估、操作审计、运行观测相关配置 |

## 技术实现

- **混合检索：**向量 MMR 与 BM25 召回，按配置引入 RAPTOR 树检索，通过 RRF 融合候选，并结合条件重排序。RRF 根据排名融合，不宜描述为固定比例的语义分数加权。
- **知识组织：**针对不同资料类型采用分块策略；RAPTOR 通过聚类与摘要组织层次信息。知识图谱和规则查询作为特定场景分支，并非所有请求均执行全部检索路径。
- **复杂问题处理：**Agentic RAG 支持问题拆解、多步检索与有限次数的反思重试；其效果仍需通过固定测试集验证。
- **工具编排：**模型输出结构化工具决策，由后端校验并执行。当前实现不等同于全面采用模型原生 Function Calling 协议。
- **MCP 会话管理：**外部连接按请求创建与释放，避免跨请求复用会话引起异步任务作用域错误；连接元信息可单独缓存。
- **访问控制：**后端按用户知识库权限约束可检索文档范围，外部 API Key 范围与账号权限共同限制访问。

## 技术栈

| 层级 | 技术 |
| --- | --- |
| 前端 | React 19、TypeScript、Ant Design 6、Vite、React Query、Zustand、ECharts |
| 后端 | Python、FastAPI、LangChain、SQLAlchemy、Alembic |
| 存储与检索 | PostgreSQL、Chroma、BM25；可选 Neo4j |

## 启动准备

需要 Docker 与 Docker Compose，以及可用的模型服务凭据。先将 `.env.example` 复制为 `.env`，配置模型密钥、随机 JWT 密钥、数据库密码及初始管理员密码，再在项目根目录执行：

```sh
docker compose up -d --build
```

主编排对外开放 HTTP 80 端口，包含前端网关、后端及 PostgreSQL；Chroma 使用持久化目录。Neo4j 和观测组件不在主编排中自动完整启动，需按相关配置另行准备。此处提供启动入口，具体环境仍需自行验证。

开发模式可分别启动前后端，相关入口见 `run.py` 和 `frontend/package.json`。启动脚本只负责拉起进程，需先安装依赖、配置环境和准备数据库。

- [MCP 接入指南](docs/MCP接入指南.md)
- [Python SDK](backend/sdk/README.md)

## 推荐演示流程

1. 管理员创建或选择知识库，上传演示资料并查看处理结果。
2. 员工登录后提出相关问题，观察流式回答和来源展示。
3. 切换不同部门账号，验证知识库访问范围。
4. 上传同名文档的新版本，展示处理成功后的版本记录与问答。
5. 展示工具调用、评估页面及审计记录，说明各自作用。

演示请自行创建虚构资料和测试账号，不在公开仓库中发布实际账号密码。

## 当前边界与后续计划

- 员工上传、管理权限及相关后端接口已存在；员工侧专用维护页面与流程尚待完善，可根据企业授权岗位配置。
- 新版本失败回滚、旧版本状态与检索过滤的一致性仍需完善和专项验证。
- 引用展示应进一步区分原始文档片段与生成摘要，便于核对证据。
- 检索稳定性、固定测试集评估及真实并发和响应时间测试仍需持续改进。
- 企业微信、SSO、外部 MCP 等集成需要对应环境配置与实际联调，代码存在不代表已完成企业上线验收。
- 运行观测、备份恢复和多实例部署还需结合实际部署环境验证。

公开展示源码不自动授予开源许可；使用与分发授权以仓库后续明确提供的许可证为准。

## 演示环境配置

公开版本不附带本地 `.env.demo`。运行演示启动器或种子脚本前，自行设置 `DEMO_ADMIN_PASSWORD` 和 `DEMO_EMPLOYEE_PASSWORD`，并配置模型、数据库及可选图谱服务。文档中的 `CHANGE_ME_DEMO_PASSWORD` 仅为脱敏占位符。

运行观测组件需设置 `CLICKHOUSE_PASSWORD`；负载测试脚本需设置 `PERF_PASSWORD`。单元测试中保留的密码字符串仅用于测试数据库中的临时虚构账号，不是可登录的部署凭据。公开仓库不包含旧提交历史、本地环境文件和实际业务数据。
