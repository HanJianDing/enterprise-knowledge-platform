# 运维手册：备份 / 恢复 / 监控告警（产品化 C）

## 一、自动备份（C1）

### 1. 备份内容与脚本

`backend/scripts/backup.py` 一次备份三样东西：

| 内容 | 方式 | 说明 |
|---|---|---|
| PostgreSQL 全量 | pg_dump（docker exec 或本机） | 全部业务数据（用户/知识库/审计/会话） |
| Chroma 向量库目录 | zip 打包 | 切片向量——**必须与 PG 同一时刻备份**（两者不一致恢复后检索会错乱） |
| uploads 上传目录 | zip 打包 | 员工上传的原始文档（重切/重试依赖物理文件） |

### 2. 部署（每天一次）

- **Linux（cron）**：
  ```
  0 3 * * * cd /srv/app/backend && python scripts/backup.py >> backup.log 2>&1
  ```
- **Windows（任务计划）**：每天一次执行 `python D:\...\backend\scripts\backup.py`
- **Docker 部署**：`.env` 里加 `BACKUP_PG_CONTAINER=<数据库容器名>`，脚本自动走 `docker exec pg_dump`

保留策略：默认保留最近 14 份，自动清理更旧的（`--keep` 可调）。

### 3. 恢复演练（必须做一次，没演练过的备份等于没有）

1. 停服务 → 在**另一台机器/目录**建干净 PG 库
2. `psql -U postgres -d ragdb < backups/<时间戳>/db.sql`
3. 解压 chroma.zip / uploads.zip 回原位
4. 启动服务 → 登录 → 抽查：文档列表正常、随便问一个问题能命中来源
5. 记录演练结果与耗时到本文件（**目标：1 小时内恢复**）

## 二、监控与告警（C4）

### 1. 健康检查接口（已升级）

`GET /health` 返回真实连通性（原来只回"healthy"，DB 挂了也报健康）：
```json
{"status": "ok", "checks": {"database": true, "vector_store": true}}
```
任一检查失败 → `status = "degraded"`。

### 2. 告警脚本（webhook 推送）

`backend/scripts/health_check.py`：拨测 /health，失败时向钉钉/企微群发消息：

```
*/5 * * * * cd /srv/app/backend && python scripts/health_check.py --url http://localhost:8000 >> health.log 2>&1
```

`.env` 配 `HEALTH_WEBHOOK_URL`（钉钉/企微机器人 webhook，text 消息体两者通用）。
**注意**：脚本与系统同机部署时只能发现"进程死了"；磁盘满/机器宕机需云端拨测兜底。

### 3. 腾讯云免费监控配置清单（服务器层，5 分钟配完）

进入 腾讯云 → 云监控 → 告警策略 → 新建：

| 监控项 | 阈值 | 说明 |
|---|---|---|
| CPU 使用率 | >90% 持续 5 分钟 | 4C4G 打满 = 即将卡死 |
| 内存使用率 | >90% 持续 5 分钟 | OOM 前预警 |
| 磁盘使用率 | >80% | 备份/日志/向量库都在涨，80% 就该清理了 |

通知对象选短信/微信，免费额度够用。

## 三、审计日志保留策略（C3）

- 表内保留近 3 个月（`scripts/purge_audit_logs.py --keep-days 90`，加入每日备份同款定时任务）
- 需要长期留存的证据：审计页"导出 CSV"功能按需导出归档
