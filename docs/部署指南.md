# 百货通智能客服 — 云部署指南

> 推荐路径：**Docker Compose 一键部署**（环境一致性、数据持久化、镜像一次构建到处运行）。
> 文档末尾附「直装部署（附录）」备选方案。
> 环境要求：Docker 20+（含 compose v2 插件）、4G 内存服务器、出站 HTTPS 可达（百炼 API 在线调用）。

## 一、部署架构（Docker）

```
用户 ── HTTP:80 ── nginx 容器 ──┬─ 静态文件     → frontend 构建产物（镜像内置）
                                ├─ /api/v1/*    → backend 容器（uvicorn 单 worker）
                                └─ PostgreSQL   → db 容器（仅内网可达，宿主机不可直连）
```

- 三个容器由 `docker-compose.yml` 编排：`db`（postgres:16-alpine）→ `backend`（自建镜像）→ `nginx`（自建多阶段镜像）
- **数据持久化**：三个命名卷（`pgdata`/`chroma`/`uploads`），容器删了数据还在
- **迁移自动执行**：backend 容器入口脚本先 `alembic upgrade head` 再启动，天然规避"先迁移后启动"的顺序坑
- **单 worker**：向量库（ChromaDB）是进程内单例 + 文件存储，多 worker 会写坏向量库，已在入口脚本固定

## 二、部署步骤（服务器上执行）

### 1. 拉代码

```bash
git clone git@gitee.com:wangqiangaaa/ai-customer-service.git /srv/ai-cs
cd /srv/ai-cs
```

### 2. 确认 Docker 可用

```bash
docker --version        # 应 ≥ 20
docker compose version  # 若无：sudo apt install -y docker-compose-plugin
```

### 3. 配置 .env（关键步骤）

```bash
cp .env.example .env
# 编辑 .env，必须设置：
#   DASHSCOPE_API_KEY   —— 真实百炼密钥
#   JWT_SECRET_KEY      —— python3 -c "import secrets; print(secrets.token_urlsafe(48))" 生成的随机串
#   POSTGRES_PASSWORD   —— 数据库强密码（Docker 模式实际生效的数据库口令）
#   INITIAL_ADMIN_PASSWORD —— 首次启动创建 admin 用（上线后建议删除该行）
```

> `.env` 含密钥，已被 .gitignore 与 .dockerignore 双重排除，绝不进 git、不进镜像。

### 4. 构建并启动

```bash
docker compose up -d --build
```

首次构建约 3-5 分钟（pip/npm 依赖下载）。启动后验证：

```bash
docker compose ps                       # 三个服务应均为 running/healthy
docker compose logs backend | tail -20  # 应看到 "启动服务 (uvicorn...)"
curl http://127.0.0.1/health            # {"status":"ok"}
```

### 5. 打开访问

- 服务器防火墙（轻量控制台 → 防火墙）放行 **80 端口**
- 浏览器访问 `http://服务器公网IP` 即可（纯 IP 访问无需备案）
- 大陆服务器 + 域名才需要 ICP 备案（纯 IP 不涉及）

### 6. 常用运维命令

```bash
docker compose logs -f backend     # 看后端日志
docker compose restart backend     # 重启后端
docker compose down                # 停全部容器（数据卷保留）
docker compose up -d --build       # 更新代码后重建重启
docker compose pull && docker compose up -d   # 仅更新 db 镜像
```

## 三、上线前安全清单

- [ ] JWT_SECRET_KEY 换成随机强值（不是开发时的值）
- [ ] POSTGRES_PASSWORD 换成强随机密码
- [ ] admin 初始密码登录后修改，并把 INITIAL_ADMIN_PASSWORD 从 .env 删除
- [ ] 客服/用户账号弱口令自查（弱用户名账号建议禁用）
- [ ] 知识库文档内容自查（不含有私人手机号等敏感信息）
- [ ] 纯 IP 访问是 HTTP 明文：管理员密码用一次性演示密码，不要用真实常用密码

## 四、备份（建议 cron 每日）

```bash
docker compose exec -T db pg_dump -U postgres -Fc ragdb > /backup/ragdb_$(date +%F).dump
docker compose run --rm --no-deps backend tar czf - -C /srv/app/backend chroma_db uploads > /backup/files_$(date +%F).tgz
```

> 数据库与向量库/上传文件必须**成套备份**（向量分块的 document_id 指向 SQL 记录）。

## 五、更新发布

```bash
cd /srv/ai-cs
git pull
docker compose up -d --build     # 入口脚本会自动跑新迁移
```

# 附录：直装部署（不用 Docker 的备选）

适用：不想用 Docker、或服务器内存紧张。步骤：装依赖（`apt install python3.12-venv build-essential postgresql nginx` + Node 20.19+/22.12+）→ 建 PG 库 → `cp .env.example .env` 填值 → `cd backend && alembic upgrade head`（**必须先于首次启动**）→ systemd 跑 `uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1`（样例见 `deploy/ai-cs.service.example`，注意 TZ=Asia/Shanghai）→ `cd frontend && npm ci && npm run build` → nginx 配置见 `deploy/nginx.conf.example`（两处致命配置：`client_max_body_size 21m`、`proxy_buffering off`）。
