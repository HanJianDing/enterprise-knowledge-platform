- **验收成果**：OCR 分流解析成功（RapidOCR），不再报"损坏"。
- **发现问题**：上传失败，文档无法解析——根因：空文本检查在 OCR 分流之前就 return，扫描件文本提取为空直接被判"损坏"，根本走不到 OCR 分流。
- **修改方向**：OCR 分流判定前移到空文本检查之前。
- **修复成果**：已修复，扫描件可正常上传并 OCR 解析成功，用户重验通过。

### 3.9 上传加密 PDF

  ④AI 调工具传空参数（-32602）——根因：决策提示词只有工具描述无参数声明
  ⑤参数声明后小模型仍概率传空——补参数错误带反馈重试
  ⑥工具成功后 LLM 硬扯"文档里没有此工具"——根因：空文档提示与工具结果打架
  ⑦工具名幻觉成来源标记（[来源test-tools.echo]）
  ⑧每问起进程拖慢问答——工具元数据按配置指纹缓存
  ⑨中途我误升级 mcp SDK 连带 starlette 1.8 导致后端启动崩溃——环境恢复（mcp 2.2.0/starlette 0.38.6/uvicorn 0.35.0）
- **修改方向**：①管理页+落库 ②先 __aenter__ 再 initialize ③用完即弃（每次调用独立起进程）④参数声明进提示词 ⑤错误反馈重试一次 ⑥tool_mode 空文档提示脱钩 ⑦非数字来源标记清理 ⑧元数据缓存。
- **修复成果**：全部修复（0945726/74facfd/314c3cc/055a070/bbbff37/ef02419/00928cb/a0ac7bf），echo 三次连测干净回显"外部工具测试成功"，用户重验通过。残留（用户拍板不修）："正在重试"提示文案。
