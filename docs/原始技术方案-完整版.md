# 企业级电商RAG知识库问答系统 — 完整技术方案（原始版）

> 这是 Plan Agent 最初生成的完整技术方案，包含 Docker 部署、Qdrant、PostgreSQL 等
> 后续根据实际约束调整为：百炼API + 无Docker + ChromaDB + SQLite

## 一、技术栈选型

### 1.1 核心技术栈总览

| 层次 | 技术 | 版本 | 选型理由 |
|---|---|---|---|
| **Web框架** | FastAPI | >=0.115.0 | 原生async、StreamingResponse支持SSE、自动OpenAPI文档、Pydantic集成 |
| **前端** | React 19 + TypeScript + Vite | React 19, Vite 6.x | 类型安全、HMR极快 |
| **UI框架** | Ant Design 5 | 5.x | 中文生态完善、企业级组件丰富、Table/Form/Upload开箱即用 |
| **RAG框架** | LangChain + LangGraph | langchain>=1.0, langgraph>=0.3.0 | LCEL管道式组合、stateful agent支持 |
| **LLM Provider** | langchain-openai (兼容协议) | >=0.3.0 | 支持OpenAI/DeepSeek/Qwen等所有兼容API |
| **Embedding模型** | BAAI/bge-large-zh-v1.5 | 1024维 | 中文MTEB榜首、HuggingFace本地部署、无API费用 |
| **向量数据库** | Qdrant | >=1.12 (Docker) | Rust编写性能极高、混合搜索、元数据过滤、生产级持久化 |
| **关系数据库** | PostgreSQL | 16 | 成熟稳定、支持pgvector备用、丰富索引类型 |
| **ORM** | SQLAlchemy 2.0 (async) | 2.0.x | 原生async/await、类型提示完善 |
| **缓存** | Redis | 7.x | 语义缓存、会话存储、速率限制计数器 |
| **任务队列** | Celery + Redis broker | 5.4.x | 异步文档处理、批量embedding |
| **文件解析** | unstructured | >=0.16.0 | 支持PDF/Word/PPT/Excel/HTML/Markdown等20+格式 |
| **对象存储** | MinIO (S3兼容) | latest | 本地开发用、生产可无缝切换阿里云OSS/AWS S3 |
| **反向代理** | Nginx | 1.27 | 静态资源、SSE缓冲关闭、HTTPS终结 |
| **容器化** | Docker + Docker Compose | v2 | 一键启动全栈服务 |

### 1.2 LLM选型建议

该系统面向中文电商场景，建议采用"本地+云端"双通道策略:

```
默认(成本优先): DeepSeek-V3 (deepseek-chat) -- 中文能力强、价格极低
备选(精度优先): GPT-4o -- 复杂推理场景
本地(数据安全): Qwen2.5-72B (vLLM部署) -- 完全离线
```

所有模型通过OpenAI兼容API统一接入，切换只需修改环境变量。

## 三、数据库Schema设计

### 3.1 实体关系图

```
users (用户)
  ├─ 1:N → conversations (会话)
  │         ├─ 1:N → messages (消息)
  ├─ 1:N → api_usage_logs (API用量日志)

documents (文档)
  ├─ N:1 → knowledge_categories (知识分类)

conversations ← 无直接关联 documents
  (RAG通过向量库检索，不依赖外键关系)
```

### 3.2 表结构详细设计

**users (用户表)**
```sql
CREATE TABLE users (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    username        VARCHAR(100) NOT NULL UNIQUE,
    email           VARCHAR(255) NOT NULL UNIQUE,
    hashed_password VARCHAR(255) NOT NULL,
    role            VARCHAR(20) NOT NULL DEFAULT 'user',  -- 'admin' | 'user'
    is_active       BOOLEAN NOT NULL DEFAULT TRUE,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    last_login_at   TIMESTAMPTZ
);
-- 预置管理员
INSERT INTO users (username, email, hashed_password, role)
VALUES ('admin', 'admin@example.com', '<bcrypt_hash_of_123456>', 'admin');
```

**conversations (会话表)**
```sql
CREATE TABLE conversations (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id         UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title           VARCHAR(255) NOT NULL DEFAULT '新对话',
    status          VARCHAR(20) NOT NULL DEFAULT 'active',
    message_count   INTEGER NOT NULL DEFAULT 0,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_conversations_user_id ON conversations(user_id);
CREATE INDEX idx_conversations_updated_at ON conversations(updated_at DESC);
```

**messages (消息表)**
```sql
CREATE TABLE messages (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    conversation_id UUID NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
    role            VARCHAR(20) NOT NULL,  -- 'user' | 'assistant' | 'system'
    content         TEXT NOT NULL,
    citations       JSONB,  -- [{"doc_id":"xxx","title":"产品手册","chunk_idx":5,"text":"..."}]
    token_count     INTEGER,
    latency_ms      INTEGER,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

**documents (文档表)**
```sql
CREATE TABLE documents (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    filename        VARCHAR(500) NOT NULL,
    original_name   VARCHAR(500) NOT NULL,
    file_type       VARCHAR(20) NOT NULL,  -- 'pdf','docx','txt','md','csv','xlsx'
    file_size       BIGINT NOT NULL,
    storage_path    VARCHAR(1000) NOT NULL, -- MinIO对象路径
    category_id     UUID REFERENCES knowledge_categories(id),
    status          VARCHAR(20) NOT NULL DEFAULT 'uploaded',
                    -- 'uploaded' → 'processing' → 'completed' | 'failed'
    chunk_count     INTEGER DEFAULT 0,
    error_message   TEXT,
    uploaded_by     UUID NOT NULL REFERENCES users(id),
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

**knowledge_categories (知识分类表)**
```sql
CREATE TABLE knowledge_categories (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name            VARCHAR(100) NOT NULL UNIQUE,
    description     TEXT,
    parent_id       UUID REFERENCES knowledge_categories(id),  -- 树形结构
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

## 五、RAG管道架构

### 5.1 整体数据流

```
用户提问
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│                    1. Query预处理                            │
│   - 检测是否为历史重复问题 (Redis语义缓存命中?)              │
│   - 多轮对话上下文改写 (将指代消解为完整查询)                │
│   - 生成多个检索变体 (Multi-Query, 提高召回率)               │
└──────────────────┬──────────────────────────────────────────┘
                   ▼
┌─────────────────────────────────────────────────────────────┐
│                    2. 混合检索                               │
│   ┌──────────────┐    ┌──────────────┐                      │
│   │  向量检索     │    │  BM25关键词  │                      │
│   │ (Qdrant)     │    │  检索        │                      │
│   │ top_k=12     │    │  top_k=12    │                      │
│   └──────┬───────┘    └──────┬───────┘                      │
│          └────────┬──────────┘                              │
│                   ▼                                         │
│          结果融合 (RRF: Reciprocal Rank Fusion)              │
│          合并去重 → 候选集 ~15-20                            │
└──────────────────┬──────────────────────────────────────────┘
                   ▼
┌─────────────────────────────────────────────────────────────┐
│                    3. 重排序 (Reranking)                     │
│   - Cross-Encoder模型: bge-reranker-v2-m3                   │
│   - 对候选集精排，取 top_k=4                                │
│   - 过滤相关性分数 < 0.3 的块                               │
└──────────────────┬──────────────────────────────────────────┘
                   ▼
┌─────────────────────────────────────────────────────────────┐
│                    4. LLM生成                                │
│   - 组装Prompt (系统指令 + 引用格式要求 + Context + 问题)    │
│   - 调用LLM流式生成                                         │
│   - 后处理: 解析引用标记 → 匹配源文档 → 附加到响应           │
└──────────────────┬──────────────────────────────────────────┘
                   ▼
              SSE流式返回给前端
```

## 六、性能优化方案

### 6.1 多层缓存架构

| 层级 | 位置 | 策略 | TTL | 预计收益 |
|---|---|---|---|---|
| **语义缓存** | Redis | 相似问题(embedding距离<0.05)→缓存答案 | 1小时 | 减少30-40% LLM调用 |
| **查询缓存** | Redis | 精确匹配query_hash→答案 | 24小时 | 减少热点问题延迟 |
| **会话缓存** | Redis | 活跃会话的消息列表 | 30分钟 | 减少数据库查询 |
| **用户缓存** | Redis | 用户信息/JWT黑名单 | 与JWT同步 | 减少鉴权开销 |

### 6.2 连接池配置

```python
# PostgreSQL
engine = create_async_engine(DATABASE_URL, pool_size=20, max_overflow=10)

# Redis
redis_client = redis.asyncio.Redis(connection_pool=..., max_connections=50)

# Qdrant
qdrant_client = QdrantClient(host="qdrant", port=6333, timeout=10.0)
```

### 6.3 流式响应优化

- FastAPI `StreamingResponse` + `text/event-stream`
- Nginx `proxy_buffering off;`
- LLM `llm.astream()` 异步流式生成
- 前端 `fetch()` + `ReadableStream`

## 十、变更说明

最终实施时根据实际情况做了以下调整：

| 项目 | 原始方案 | 实际方案 | 原因 |
|---|---|---|---|
| LLM | OpenAI/DeepSeek API | 阿里云百炼 DashScope (qwen-plus) | 国内访问方便 |
| Embedding | bge-large-zh本地 | 百炼 text-embedding-v2 | 云端调用，降低硬件要求 |
| 向量数据库 | Qdrant (Docker) | ChromaDB | pip安装，无需Docker |
| 关系数据库 | PostgreSQL | SQLite | 零安装，单机部署 |
| 缓存 | Redis | diskcache | 无需额外服务 |
| 文件存储 | MinIO | 本地文件系统 | 简化部署 |
| 任务队列 | Celery | FastAPI BackgroundTasks | 减少依赖 |
| 部署 | Docker Compose | 命令行直接启动 | 网络限制 |
