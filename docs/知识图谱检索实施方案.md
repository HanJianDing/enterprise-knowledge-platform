# 知识图谱检索（GraphRAG）实施方案

> 目标：为自研企业知识库系统增加图谱检索能力，解决向量+BM25 检索的短板——多跳关系类问题（如"张三和王五什么关系"）。
> 依据：RAGFlow 0.27.2 源码调研（`rag/graphrag/` 主线实现，调研报告见 Temp\ragflow_graphrag_research.md）+ 自研项目现状。
> 状态：待用户拍板后开发。

## 一、核心设计决策（先看这个）

### 决策 1：用 Neo4j 真图库，但抽取管线全套借鉴 RAGFlow

调研最重要的发现：**RAGFlow 自己不用图数据库**——它把实体/关系"拍平"存进文档检索库（ES），多跳靠建图时预计算的 2-hop 路径 + 检索时打分展开，全程没有 Cypher 遍历。

我们的选择：**装 Neo4j 做真遍历**。理由：

| | RAGFlow 拍平方案 | 我们的 Neo4j 方案 |
|---|---|---|
| 多跳 | 预计算 2-hop，超过 2 跳查不到 | Cypher 任意跳数、路径查询、聚合统计（"谁的下属最多"） |
| 可视化 | 无原生图视图 | Neo4j Browser 直接看图谱（面试演示的视觉冲击） |
| 成本 | 零新依赖 | Java 服务，512M 堆（4C4G 演示可接受） |

同时**照搬 RAGFlow 成熟的抽取设计**（这是它踩坑最多的地方）：抽取批打包、light 抽取提示词、实体类型白名单、关系质量过滤、实体消歧流程、查询重写+实体链接、图谱上下文合并方式。等于：**RAGFlow 的"抽图智慧" + Neo4j 的"查图能力"**，两者取其长。

### 决策 2：先做"关系类问题"窄场景，不贪全

建图只针对句式规整的文档（组织架构、审批链、"XX由XX负责"类制度），抽取准确率可控；其他文档不进图。与 RAGFlow 的"KB 级开关"同思路：图谱是按库可选开关。

### 决策 3：图谱结果 = 合成伪块置顶 + 独立引用格式

RAGFlow 的做法：图谱查询结果组织成一个合成 chunk 插到向量检索结果**第 0 位**，用 `[KG]` 标记区分来源，与普通 `[来源N]` 一并喂给 LLM。我们照搬，改动最小、效果直接。

## 二、总体链路

```
文档上传/重切完成
  → 图谱任务入队（job 表新 task_type="graph_build"）
  → 按文档抽取批（chunk 按 4096 token 重打包）
  → LLM 抽取三元组（light 提示词：实体+类型+关系+关键词+强度）
  → 过滤（实体类型白名单 + 关系质量规则）
  → 写入 Neo4j（节点带 source_id 文档来源，边带权重/描述）
  → 实体消歧（可选二阶段：粗筛 + LLM 确认 + 连通分量合并）

用户提问
  → classifier 识别 relation 类（新增复杂度类型）
  → 查询重写：LLM 从问题抽实体名（entities_from_query ≤5，失败回退整句）
  → Neo4j：定位实体 → 取 1~2 跳路径/邻居子图 → 实体 top6 + 关系 top6
  → 组织成 CSV 文本（实体表 + 关系表 + 路径）
  → 合成伪块置顶插入向量检索结果 → LLM 生成（[KG] 引用格式）
```

## 三、三步走路线（每步可验收）

### 第一步：最小闭环（约 3~5 天）

| 项 | 内容 |
|---|---|
| 环境 | 装 Neo4j Community（本地 zip 版，限制堆 512M，D:\Neo4j） |
| 后端新包 | `backend/app/rag/graph/`：`prompts.py`（抽取/查询重写提示词，借鉴 light 版）、`extractor.py`（批打包+LLM 抽取+白名单/质量过滤）、`neo4j_store.py`（连接池、写入节点/边、按 source_id 删子图、1~2 跳遍历查询） |
| 配置 | .env 加 NEO4J_URI/USER/PASSWORD；KB 级开关 use_graphrag（默认关，演示库开） |
| 建图 | 组织架构/审批类文档上传完成后触发图谱任务（复用 job 表状态机） |
| 查询 | classifier 加 relation 类型；chat_service 图谱上下文合成伪块置顶 + [KG] 引用 |
| 验收 | 演示库挑 2~3 份"XX的上级是XX"类文档建图，问"张三和王五是什么关系"答出"隔着李四"；问普通问题不受影响（回归评估集持平） |

### 第二步：把质量立起来（约 1 周）

| 项 | 内容 |
|---|---|
| 实体消歧 | 照搬 RAGFlow：字符相似度粗筛 → LLM 确认 → 连通分量合并（"张总/张三/张先生"归一人） |
| 增量更新 | 文档删除→按 source_id 删子图；文档重切→先删旧子图再重建（job 表挂钩） |
| 评估集 | `eval/queries_relation.json`：20~30 道关系题（1 跳/2 跳/路径/聚合），管理页可视化跑分 |
| 调优 | 抽取提示词迭代、强度阈值、topN 参数，用评估集量化 |
| 验收 | 关系题 hit-rate ≥ 85%；普通题评估持平；文档删除后图谱同步干净（Neo4j 查无残留） |

### 第三步：进阶（可选，约 1 周）

| 项 | 内容 |
|---|---|
| 全局性问题 | 聚合类问题（"哪个部门的人最多"）走 Cypher 统计查询 |
| 图谱可视化页 | 前端管理页用 neo4j 数据画关系图（面试演示高分项） |
| KB 开关 UI | 知识库管理页加"启用图谱检索"开关 + 手动重建图谱按钮 |
| 验收 | 剧本场景 9：关系问答演示（含可视化） |

## 五、工作量与成本

| 项 | 估算 |
|---|---|
| 第一步 | 3~5 天（含装环境、抽取管线、查询链路、端到端验收） |
| 第二步 | 1 周（消歧、增量、评估集、调优） |
| 第三步 | 1 周（可选） |
| LLM 成本 | 建图是离线批处理：每文档一次抽取调用（几十个 chunk 合成 1~3 个 4096-token 批），演示库 60 主题制度类文档约几十次调用，可控 |
| 机器资源 | Neo4j 512M 堆 + PG + Chroma + 后端，4C4G 演示可同时跑（Neo4j 只在演示/评估时启动即可） |

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 抽取质量差（错关系/错实体） | 先挑句式规整文档类型；白名单+质量过滤规则；评估集量化准确率，低于阈值不铺开 |
| 实体对不上（"老张" vs "张三"） | 第一步朴素匹配可接受；第二步实体消歧+别名规则 |
| 脏图比没图更糟（一本正经答错） | [KG] 上下文里带强度/来源，提示词要求"图与文档冲突时以文档为准"；图谱命中低时不走图谱 |
| Neo4j 内存占用 | 限制堆 512M；不用时服务不启动，查询层做连接失败降级（图谱不可用→走纯向量检索） |
| 增量不一致 | 删文档/重切全挂钩 job 表；测试覆盖"删后无残留" |

## 七、面试叙事（做完后怎么讲）

"向量+BM25 解决'直接提问'，图谱解决'关系链条'——我的检索是三层：全文关键词（BM25）、语义向量（MMR+RRF+重排）、知识图谱（Neo4j 多跳遍历），问题先分类再选路，图谱结果与向量结果合并注入。建图借鉴了 RAGFlow 的抽取管线（light 抽取+实体类型白名单+关系质量过滤+实体消歧），但查询层用真图遍历替代了它的 2-hop 预计算，支持任意跳数和聚合问题；同时做了 KB 级开关和 fail-closed 降级，图谱不可用时自动回退纯向量检索。"
