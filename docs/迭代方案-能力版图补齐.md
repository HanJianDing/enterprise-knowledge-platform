## 评估体系演进（贯穿所有批次）

> 用户 2026-10-04 指正：新增文档和新功能后，既有评估集无法完整覆盖项目——**评估集随批次分层扩展，旧题永为回归基线**。

| 评估层 | 内容 | 何时新增 | 口径 |
|---|---|---|---|

| **语料层** | 超长文档题（员工手册细节/年报数据/会议决议）+ 通知类题，约 +15~20 题 | 批次 0 完成后 | 新题全绿 |
| **检索专项层** | 同义词题（"报销怎么走"→期望命中费用报销制度）、长文档章节题、宏观题（RAPTOR 评估用），约 +10 题 | 批次 1 | 专项命中可量化 |

| **回答质量层**（既有） | eval_answer_quality + judge | 涉及提示词改动的批次（1/2/4） | 评分不降 |
| **压测层** | locust 基线（P95 延迟） | 批次 3 | 前后对比有据 |

**工程实现**：eval/ 目录多文件并存（queries.json 回归 / queries_long.json / queries_relation.json）；EvalPage 支持选择评估集（前端小改，约 1 人日，归入批次 1）。

## 批次 1：检索提准（④）

**目标**：检索层增量增强，每项独立可回退、评估集量化收益。

| 子项 | 内容 | 工作量 |
|---|---|---|
| 1a | **同义词表 + 词权重**（BM25 腿内增强）：企业术语映射（报销=费用报销、OA=办公系统），管理页可维护 | 2~3 人日 |
| 1b | **pagerank 加成信号**：文档互相引用关系算重要度，RRF 融合后 ×(1+α·pagerank) 加成式接入（相关度定大局、重要度决胜）；α 评估集实测 | 1~2 人日 |
| 1c | **TOC 感知检索 + 子分块**：目录索引（长文档章节级召回）+ 父子双层分块（小块匹配、大块给上下文） | 3~4 人日 |
| 1d | **KB 级检索参数配置**：阈值/权重/top_k 按库可调，管理页表单 | 1~2 人日 |
| 1e | **rerank provider 抽象**：云 API / 本地 OpenAI 兼容两种实现可插拔（现有 RERANK_API_BASE 只有一半） | 1~2 人日 |
| 1f | **RAPTOR 评估**：批次 0 语料就绪后用"宏观问题"实测——有收益才做，无收益记结论不开发 | 先评估后决策 |

**架构原则（面试要点）**：不改成三路加权和——RRF 排名融合无需分数归一化是融合方法选择；增量信号以"腿内增强 + 加成信号"接入。

**验收标准**：回归层 hit-rate 不降；**新增检索专项题 +10 题**（同义词/长文档章节/宏观题）全绿且专项命中可量化；每子项可独立回退（基线 98.21%）。

## 批次 3：可观测栈（②）

**内容**：docker-compose 新增 OTEL Collector + Jaeger + ClickHouse 三服务；FastAPI 接入 opentelemetry-instrumentation；RAG 管线各阶段 span 埋点（分类/拆解/子检索/重排/LLM 生成，带命中块数/token 属性）。

**三个关键点**：
1. 埋点质量是灵魂（span 层次 = 管线架构的可视化）
2. 演示场景：locust 压测 → Jaeger 定位瓶颈 → 优化前后 P95 对比（"有证据的性能故事"）
3. 产品桥接：聊天回答详情显示 trace_id，点击跳 Jaeger

**验收**：压测 100 并发下 Jaeger 能看到完整链路；挑一条慢请求讲出瓶颈定位；locust P95 延迟基线建立（后续批次回归对比）。
