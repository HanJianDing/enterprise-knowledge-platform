# A1 分块模板化实施方案（借鉴 RAGFlow）

> 目标：让"答得准"从运气变成结构。现在统一切分，表格被压扁、条款没上下文、问答对可能被切断。
> 原则：**改动只在"加载→分块"环节，检索与向量库零改动**；新策略只影响新上传/重新处理的文档；评估集 91.67% 是验收红线。

## 一、现状诊断（已核实代码）

| 环节 | 现状 | 问题 |
|---|---|---|
| 加载 | txt/md/pdf/docx/csv → 纯文本；**不支持 xlsx** | CSV 被压平成"行1: 列A: x \| 列B: y"，表头信息在分块时丢失 |
| 分块 | 4 策略：structured 整块 / faq 双换行切 / long_text 递归 600/100 / default 500/80 | 全是"按标点+长度"盲切：表格行会被切断、条款"第X条"没有章节上下文、问答对靠双换行运气 |
| 内容类型 | 上传时人工选（faq/structured/long_text/chat_log） | 没有"表格""条款"选项 |

## 二、新增三种模板 + 通用升级

### 1. 条款模板（laws）——制度类文档，**自动识别，不新增选项**
- **检测**：文本中"第X条/第X章/第X节/一、二、"等条款编号的出现密度达标（如每 500 字 ≥ 2 处）→ 自动走条款切分，否则回落普通 long_text
- **切法**：按"第X章/节 → 第X条"两级边界切，每条条款一个块，小块合并至目标尺寸（≈400 字）
- **上下文注入**：每个块的正文前缀写入章节路径，如：
  > 【第五章 假期管理 → 第十二条 婚假】员工结婚可享受婚假 3 天……
- **元数据**：`section_path`（章节路径）+ `chunk_type="laws"`，分块查看页展示路径标签
- **验收**：上传《考勤管理制度》→ 问"婚假几天"命中带条款路径的正确切片；分块页能看到条款结构

### 2. 问答对模板（qa）——FAQ 文档，**升级现有 faq 策略**
- **检测**：按问答标记识别（`Q:/A:`、`问：/答：`、`Q1.` 等）成对切分；识别不到时保持现有双换行切分（不劣化）
- **切法**：一个问答对 = 一个块，问题保留为块的开头（检索时问题文本天然参与匹配）
- **合并**：过小的相邻问答对合并（保证块 ≥ 100 字，避免碎片）
- **验收**：上传《IT常见问题》→ 问"VPN 连不上怎么办"命中完整 Q/A 对，不会只命中半个答案

### 3. 表格模板（table）——Excel/CSV，**新增上传选项 + 新增 xlsx 支持**
- **xlsx 支持**（新增依赖 openpyxl，纯 Python）：每个 sheet → "表名 + 列头 + 数据行"；魔数校验同步加白名单
- **切法**：按行分组（约 20 行/块），**每块开头重复注入列头上下文**：
  > 【表格：报销标准】列：项目, 限额, 说明
  > 行1: 市内交通 | 100元/天 | 凭发票报销
  > 行2: ……
- **csv 复用同策略**（现有 CSV 压平逻辑升级为表结构感知）
- **元数据**：`chunk_type="table"` + `table_header`（列头）
- **验收**：上传《报销标准.xlsx》→ 问"市内交通费每天限额"命中带表头的正确切片

### 4. 通用长文本升级——标题层级合并
- long_text 切分前先按 Markdown 标题（`#/##/###`）或"一、二、"式编号分段，段内递归切分时**段标题作为前缀注入每块**（借鉴 RAGFlow naive_merge 的层级合并思路）
- 效果：长手册类文档每块都自带"在讲哪一节"，检索命中后 LLM 上下文更连贯

## 三、存量文档怎么办

- 现有文档保持旧分块不动（不静默重切，避免烧嵌入成本）
- **新增"重新分块"动作**：文档列表对 completed 文档加"重切"按钮 → 调 `reprocess` 接口新增 `force=true` 参数（默认仍仅 failed 可重试，守住之前的质量修复），确认弹窗提示"将删除旧分块并按当前模板重新处理"
- 验收时对样例文档点"重切"即可看到新分块效果

## 四、不做的事（明确边界）

| 不做 | 理由 |
|---|---|
| PDF 表格结构识别（版面分析） | 需要 DeepDoc/OCR 级方案，属阶段 D 可选升级；本期只做 xlsx/csv 原生表格 |
| 切片可视化编辑（RAGFlow chunk 页） | 工作量大、收益边际；分块查看页（已有）先满足"看见" |
| RAPTOR / 多级摘要 | 已确认不引入 |
| 自动选择模板（AI 判断文件类型） | 规则检测已足够（条款密度/问答标记/文件扩展名），不烧 token |

## 五、实施顺序与验收门

| 子批次 | 内容 | 验收门 |
|---|---|---|
| **A1-1**（后端核心） | chunker 三模板 + 标题层级合并 + 单测（每策略 ≥3 用例） | 后端全绿 |
| **A1-2**（表格+格式） | xlsx 加载（openpyxl）+ 魔数白名单 + 上传选项 + 前端表格模板展示 | 上传 xlsx 全链路通过 |
| **A1-3**（存量+回归） | force 重切 + 前端确认弹窗 + **60 题评估集跑分** | 评估 ≥ 91.67% 不降、双端全绿、gitcommit-agent 提交 |

## 六、风险评估

| 风险 | 应对 |
|---|---|
| 条款密度误判（普通文档出现"第一条"字样） | 阈值保守 + 单测覆盖误判样本；误判最多是分块方式不同，不产生错误内容 |
| 表格行组切分割裂行上下文 | 列头注入每块 + 行组边界按行整行切（不切半行） |
| 存量重切烧嵌入成本 | 仅手动触发 + 确认弹窗提示成本 |
| openpyxl 解析异常（加密/损坏 xlsx） | 异常捕获走现有 error 流程，错误信息进解析流水（A3 已就位） |
